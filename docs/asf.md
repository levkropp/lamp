# ASF audio

LAMP 0.4.0-dev reads local, unencrypted ASF files with a handwritten assembly demuxer in `src/asf.s`. The Windows open filter and folder discovery include `.asf`, `.wma` and `.wmv`; the audio codec inside the file determines whether it plays. **WMA decoding is still unsupported.** Video is skipped.

The Header Object, File Properties and Stream Properties identify the audio streams. Automatic selection takes the first supported, unencrypted, unscrambled audio stream. `--track N` and the Windows Audio track menu count every audio Stream Properties object, including unsupported and encrypted streams, in header order. IDs 1–127 are supported; duplicate IDs and ID zero reject. Header Extensions are bounded independently and can contain Stream Properties.

The codec policy is shared with [AVI](avi.md): PCM and float, G.711, IMA/Microsoft/Duck ADPCM, MPEG Layers I–III, AC-3 and AAC. PCM and G.711 retain the existing WAVE channel-layout and stereo-mixing rules. The demuxer gathers complete selected media objects behind a Wave64 header and opens the existing WAVE decoder. AAC with an AudioSpecificConfig instead uses each completed media object as a packet in the track layer; AAC without a configuration is gathered as ADTS. The gather reservation is bounded by the packet-data span rather than the whole file; a large skipped header does not reserve equivalent audio memory. Its address stays fixed, so packet pointers survive subsequent appends, and it is released by `mts_close`.

Packets may contain one or several payloads, several small compressed media objects, or fragments of an object continued in later packets. All four variable-field length codes, optional error-correction data and padding are bounded before reads. The demuxer validates selected object numbers, offsets and sizes: missing, overlapping, reordered, contradictory or incomplete fragments reject rather than joining unrelated bytes. It supports fixed packet sizes, explicit variable packet lengths and logical packets padded up to the declared minimum physical size. Broadcast headers can leave the Data Object size/count unknown; their local packet data must still be complete.

Object sizes and mapped offsets are 64-bit. Packet and selected media-object sizes are limited to 16 MiB, format data to 65,553 bytes (18 + the maximum WAVEFORMATEX private-data length), stream IDs to 127, header objects to 4,096 and Header Extension recursion to four levels. Unknown header objects are skipped by their validated size. The Header Object child count and Data Object packet count are checked. FFmpeg 9.0.1 omits its single Marker Object from the child count: LAMP permits exactly that one-object undercount when there is one top-level marker of at least 48 bytes. Other count mismatches reject, and all object-size/end/work limits still apply. Parsing checks cancellation between objects and payloads. ASF indexes are skipped: seeking uses the existing decoder's sample/frame index after the selected audio has been gathered.

Unsupported or unfinished: WMA variants, other codecs outside the shared AVI policy, scrambled spreading spans above one, DRM, DVR-MS and audio described only through Extended Stream Properties, network ASF chunk framing, timestamp gaps/reordering, non-default metadata languages and native surround output. The audio timeline is consecutive decoded samples; header play duration, preroll and presentation timestamps do not insert silence or trim samples. Files truncated inside declared objects or packets reject. An unavailable selected audio track rejects with error 101; invalid ASF framing rejects with 100. An inner decoder can return its own format error.

## Tags and pictures

The original assembly reader in `src/tags_asf.inc` reads Content Description, Extended Content Description, Metadata and Metadata Library objects, including those in bounded Header Extensions. `lamp-cli --tags` exposes the same ten normalized keys as other containers. Title, Author and Description map to title, artist and comment; WM/AlbumTitle, WM/AlbumArtist, WM/Year, WM/TrackNumber, WM/PartOfSet, WM/Genre, WM/Comments and WM/Composer provide the remaining mappings. Canonical key names also work. Names must be complete ASCII UTF-16LE strings and match without regard to ASCII case. Unicode values convert from UTF-16LE, stop at their first NUL or unpaired surrogate, and retain at most 4,096 UTF-8 bytes at a character boundary.

Global attributes (stream number zero) provide fallback values. Attributes with the opened audio stream's actual ASF ID replace them, regardless of where stream properties appear in the header. Other streams and nonzero language indices are skipped. Within either scope, the last nonempty value for a normalized key wins. Fixed per-key staging prevents repeated attributes from exhausting the shared tag arena. WORD, DWORD, QWORD and BOOL values use full unsigned decimal conversion; BOOL has four bytes in Extended Content Description and two in Metadata/Library. Scalar widths must match the declared type. GUID values and arbitrary binary values are skipped; deprecated zero-based WM/Track and ID3 byte-array attributes remain unread.

Binary WM/Picture attributes use the packed type/size, terminated UTF-16LE MIME and description, then image bytes described by [Microsoft's ASF_FLAT_PICTURE documentation](https://learn.microsoft.com/en-us/windows/win32/api/mfidl/ns-mfidl-asf_flat_picture). A valid selected-stream picture takes precedence over global pictures; within that scope the first front cover (type 3), or otherwise the first picture, is kept. An invalid local picture cannot erase a valid global one. MIME names are case sensitive, and the declared JPEG/PNG/GIF/BMP/TIFF/WebP type is retained without changing the image bytes. MIME strings allow at most 63 ASCII units plus their terminator; descriptions allow at most 4,095 UTF-16 units plus their terminator. Metadata Library's DWORD value size supports pictures larger than Extended Content Description's WORD capacity. Pictures point into the mapped file and use the existing export and Windows WIC display paths.

The reader bounds every descriptor against its own object, preflights a descriptor list before publishing any of its tags or pictures, and checks cancellation. Malformed optional metadata is skipped without setting an audio error or changing PCM. Unknown objects are skipped by size. Each of the two scope passes permits at most 4,096 objects, 65,536 descriptors and four Header Extension levels; a descriptor group exceeding the remaining budget is skipped. Nothing after the Header Object is searched for tags or images.

`tests/verify-asf-metadata.py` prepares versioned FFmpeg and independent serializer fixtures, checks CLI and guarded-reader results, and compares global tags and attached pictures with FFmpeg. The maximum unsigned DWORD case records FFmpeg 5's sign extension separately: LAMP and FFmpeg 9 preserve `4294967295`. WMA remains an open codec task: the reviewed [FFmpeg WMA tables](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/libavcodec/wmadata.h) carry LGPL notices, and a purported public-domain [uwma header](https://github.com/yui0/slibs/blob/master/uwma.h) contains GPL/libwma declarations. Neither was accepted as a compatible permissive runtime source; no WMA source or tables have been added to LAMP.

## Marker chapters

`src/chapters_asf.inc` reads the first structurally valid Marker Object in the Header Object, including within the existing four-level Header Extension limit. `lamp-cli --chapters` lists its entries in stored order; the existing console/player bracket keys and Windows chapter menu use their chronological starts and retain pause. Markers are global and do not change with the audio track choice.

Timing follows [Microsoft's ASF specification, revision 01.20.03, section 3.7](https://go.microsoft.com/fwlink/?LinkId=89814) and [the documented preroll adjustment](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-dlnhnd/87df71b4-4092-4cd9-84f3-2a1deae3d9d2): subtract File Properties preroll in milliseconds from the marker's presentation time in 100-nanosecond units. Top-level File Properties is discovered first, so its position in the header cannot change chapter timing. Conversion to the shared nanosecond timeline checks multiplication and subtraction. Before-preroll markers and times that cannot fit unsigned 64-bit nanoseconds are skipped. Offset, send time and reserved flags do not steer the audio decoder; navigation uses its exact sample/frame seek path.

The object name length counts UTF-16 bytes, while each description length counts UTF-16 units. Entry Length must equal 12 plus the description byte count. Names must have an even byte count; counted strings may omit a terminator. Titles convert from UTF-16LE to UTF-8, stop at NUL or an unpaired surrogate, and use the shared 1,024-byte title limit and 256 KiB arena. Up to 1,024 representable starts are retained. A separate 65,536-entry preflight budget bounds marker work without using the tag descriptor budget. Every entry must fit and the entries must consume the object exactly before any chapter is published; malformed objects can be followed by a valid one. Cancellation is checked during discovery, preflight and publication. Audio, tags and artwork do not depend on marker validity.

These rules intentionally differ from FFmpeg's permissive reader on malformed entry lengths/trailing bytes, repeated Marker Objects, negative starts, overflowing nanoseconds and a Marker Object placed before File Properties. Long titles use LAMP's shared cap rather than FFmpeg's 1,023-byte marker buffer. Valid ordinary files and independent layouts within those limits are compared with both FFmpeg 9.0.1 and 5.1.9.

Its 55 layouts include three actual FFmpeg 9 muxer files, unsorted/duplicate/fractional starts, header-order independence, Unicode paths/titles, capacity limits, maximum counted strings, malformed entries, cover retention and isolated metadata ending directly at a protected page. Both builds pass 43,306 protected reads, 43 exact PCM envelope comparisons, four continuous decodes and 64 exact heard-file seeks after decode-ahead at 44.1/48 kHz, with 1,200 native and 120 Wine mutations. Native PCM is compared with FFmpeg 5.1.9; Windows PCM equals that verified native output byte for byte. Console bracket keys and paused navigation are observed at a private sink. Native playback uses a private D-Bus session to avoid the shared PulseAudio name collision; Wine additionally inherits the recorded per-process address-randomization workaround. `--prepare-only` makes versioned fixtures and `--wine-only` repeats a completed native run using the shipping COFF objects. `--baseline-cli PATH` requires the binary hash from the published ASF metadata report: three cases retain identical PCM while adding chapters, and three muxer cases reproduce the previous header-count rejection.

The [three Wine player scenarios](../reports/asf-chapters-player-verification.json) observe ASF and FLAC heard-file chapter controls, including focused bracket keys, menu commands, out-of-duration markers, paused silence and resumed PCM, plus the existing ASF Unicode title/cover track-switch scenario. Existing [ASF audio](../reports/asf-chapters-audio-regression-verification.json), [ASF metadata](../reports/asf-chapters-metadata-regression-verification.json) and [chapter reader](../reports/asf-chapters-reader-regression-verification.json) regressions pass 93/57/40 checks. Metadata and chapter-reader regressions include 1,200/1,100 mutations. All reports retain current source/binary provenance; the Wine report verifies that the CLI rebuilt by the GUI runner differs from the retained tested CLI only in its PE linker timestamp. Native Windows devices, WIC and screen readers remain unverified.

`python3 tests/verify-asf.py` creates independent packet layouts and files from FFmpeg's ASF muxer, checks continuous PCM and indexed seeks, verifies audio catalogs and failure clearing, and tests cancelled open/read. `--prepare-only` creates fixtures on a host with FFmpeg; `--wine-only` repeats a completed native run using the shipping Windows COFF objects. The metadata suite records [57 native checks](../reports/asf-metadata-verification.json) and [57 Windows/Wine checks](../reports/asf-metadata-wine-verification.json): 56 tag/art cases, 58,526 protected reads and 47 exact PCM comparisons per build, plus 1,200 native and 120 Windows mutations. Existing tags/cover suites each pass 50 regression checks, including 1,200/1,000 mutations; the existing ASF audio suite passes all 93 checks with playback skipped. These tests do not verify native Windows WIC, devices or screen readers.

The recorded [96 native checks](../reports/asf-verification.json) and [93 Windows/Wine checks](../reports/asf-wine-verification.json) include 1,200 exact seek comparisons and 1,482 protected input checks per build. [Ten GUI checks](../reports/asf-player-verification.json) cover file-list construction and real-popup track switches across seven containers. The [negative controls](../reports/asf-negative-control-verification.json) retain their separate published-parent and uncommitted-gather provenance. Shared WAVE/AVI regressions pass 78/80 checks.

The recorded suite covers the cases below; Duck ADPCM, Layer I and HE-AAC reuse the shared codec policy but do not yet have ASF-specific interoperability fixtures. The muxer cases include integer/float PCM, mono/stereo G.711 and ADPCM, MPEG audio, AC-3, AAC, multichannel PCM, skipped WMV2 video and real WMA ahead of PCM/MP3. Constructed layouts cover field widths, omitted fields, compressed objects, fragments splitting samples, object-number wrap, variable packets, broadcast headers, nested extensions, Unicode paths and all 127 stream IDs. Unsupported format placeholders in the capacity case establish catalog bounds, not WMA interoperability. Protected input tests place the exact mapped end immediately before `PAGE_NOACCESS`; a sparse input skips an unknown header object larger than 4 GiB while comparing the complete PCM.

Continuous output is compared independently against FFmpeg and against the same format/audio bytes in WAVE (ADTS for AAC). FFmpeg's ASF-to-WAVE stream copy estimates a WAVE `fact` count from millisecond timestamps; the test removes this invented trimming field while retaining the exact `fmt` and `data` bytes. The ASF-to-PCM comparison uses the original ASF, with `mp2float` for Layer II. MPEG/AC-3/AAC synthesis retains the existing decoder tolerances. The current four-bit WAVE IMA decoder and FFmpeg 5 use a combined reconstruction product; FFmpeg 9 uses separate shifts. Its comparison alone allows a peak difference of 127/32768; the WAVE comparison, FFmpeg 5 comparison, seeks and native-versus-Windows PCM remain exact. AC-3 dither noise restarts after seeking, as [documented for the decoder](ac3.md); its ASF seeks must equal seeks in the identical raw audio bytes. A separate dither-free AC-3 case checks exact seeks against continuous output. AAC fixtures disable perceptual noise substitution for that same continuous-output check.

The implementation is original MIT-licensed assembly. Container organization was checked against [Microsoft's ASF file structure](https://learn.microsoft.com/en-us/windows/win32/medfound/asf-file-structure), and byte-layout/interoperability behavior against the versioned primary [FFmpeg 9.0.1 demuxer](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/libavformat/asfdec_f.c), [muxer](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/libavformat/asfenc.c) and [GUID declarations](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/libavformat/asf_tags.c). No FFmpeg source is linked or invoked by LAMP; FFmpeg is a test comparator. Native Windows devices and screen readers remain unverified.

The sparse-file check records a 4,295,010,132-byte logical file with 49,152 allocated bytes. Wine 8 returns the logical size from `GetCompressedFileSizeW` for this file; the oracle also checks `FILE_STANDARD_INFO.AllocationSize` and retains the smaller allocation report. Both values are recorded. A saved uncommitted ASF binary reproduces the original whole-file gather allocation failure; the fixed binary decodes the same sparse layout. The published parent rejects the ordinary ASF fixture because it has no ASF demuxer. These are separate negative controls, with their binary/source hashes retained in the report.

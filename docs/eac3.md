# E-AC-3 partial profile

LAMP 0.4.0-dev adds a handwritten E-AC-3 parser in `src/eac3.inc`, spectral reconstruction in `src/eac3_spx.inc` and adaptive hybrid transform mantissas in `src/eac3_aht.inc`, sharing bit allocation, IMDCT, overlap, speaker mixing and the track layer with [AC-3](ac3.md). This is a partial E-AC-3 profile; enhanced coupling and dependent substreams remain roadmap work.

## Profile v3

- Independent and AC-3-converted substream 0, bitstream ids 11–16, 32/44.1/48 kHz, all eight channel modes with optional LFE, downmixed to stereo using LAMP's speaker weights.
- Frame lengths of 1, 2, 3 or 6 blocks (256, 512, 768 or 1,536 samples), including lengths changing within a stream. Sync frames are bounded to 4,096 bytes. Packets can hold several whole frames; the decoder checks output capacity before every frame.
- Conventional AC-3 mantissa quantizers, per-block and lookup-table exponent strategies, ordinary coupling with default or explicit band structures, implicit first coupling coordinates and leaks, phase flags, rematrixing, block switching, dither, dynamic range, frame-level SNR and FFmpeg-compatible block-0 SNR packing, separate fast gains, delta bit allocation and skip fields.
- Spectral extension (SPX): mono's implicit selection and per-channel selection in other modes, all copy/start/end codes within valid ranges, default/explicit/reused bands, implicit first and reused coordinates, all blend/master/exponent/mantissa codes, and all 32 attenuation codes. Float synthesis translates the coded coefficients, computes band RMS before attenuation, filters band boundaries and wrap points, and blends the signal with the same LFG used for mantissa dither. Ordinary coupling ends at the SPX start, and exponent/rematrix ranges follow the selected channels.
- Adaptive hybrid transform (AHT) in eligible six-block channels, including coupling and LFE channels, partial channel selection and SPX combinations. The decoder uses the high-efficiency allocation table, all 956 six-dimensional VQ vectors, all four gain modes, ternary grouped gains, small/escaped scalar mantissas, asymmetric remapping and a fixed-point six-point inverse cosine transform. Block zero reconstructs all six blocks into a bounded cache; later blocks apply their reused exponents without consuming more mantissa bits. Reserved gain-group codes 27–31 clamp to 26, agreeing with FFmpeg's concealment behavior.
- Mixing, informational, converter, additional bitstream and transient fields are parsed to preserve bit alignment. Mixing/program-scale metadata does not override LAMP's speaker weights, transient pre-noise processing is not applied, and additional object metadata is not rendered.
- Raw `.ec3`, `.eac3` or `.ac3` sync streams, Matroska `A_EAC3`, progressive/fragmented MP4/MOV `ec-3`, and MPEG-TS using ATSC stream type 0x87, DVB descriptor 0x7a or `EAC3` registration. Raw recognition uses content. CLI track selection works through the existing container layer.

Per-block SNR-offset updates beyond the FFmpeg-compatible block-0 packing are outside this profile. The published Annex E pseudocode describes another packing for those updates; general acceptance of that syntax is not claimed. Each frame must initialize its SNR offsets; older-frame SNR reuse is rejected. If a frame uses coupling, it must begin in block 0; late-start coupling in the block-0 packing could inherit offsets from older frames and prevent exact seeking, so it is explicitly rejected.

Enhanced coupling, dependent channel substreams, additional independent substreams, reduced sampling rates, older-frame SNR reuse, and coupling first activated after block 0 return `decode_error=101`. Unsupported tools fail when their syntax is encountered; they are not replaced by concealment. Atmos/object rendering, dependent-channel reconstruction and complete E-AC-3 conformance are not claimed.

Malformed framing, layout/rate changes, reserved frame types and insufficient output capacity fail. CRC errors conceal the entire frame; invalid block contents conceal the remaining blocks using the previous block, as in the AC-3 decoder. A truncated final raw frame is dropped. Leading ID3v2 and trailing ID3v1 tags are skipped.

## Timing and validation

Sample counts come from each sync frame's block count. The shared track layer honors MP4 edit lists and packet durations, and a seek decodes the preceding packet to rebuild the overlap. Dither-free conventional streams seek exactly; dither after a seek has the same level but a different generator position. SPX also advances the LFG when mantissa dither is disabled. Noisy SPX seeks restart that noise sequence. Exact SPX seek tests use nonzero translated signal, zero noise blend in every band, fresh coordinates and a stable band structure; they do not claim continuous-noise identity after arbitrary seeks.

AHT zero-bit bins always draw six LFG values, regardless of the channel's ordinary dither flag. Noisy AHT seeks are therefore compared to fresh primer decodes. Exact AHT seek fixtures verify that no zero-bit AHT bins occur; disabling the ordinary dither flag alone does not establish exact continuous-noise seeking.

The E-AC-3 frame path separates block parsing from synthesis in `src/eac3_blocks.inc`. It snapshots at most six blocks of parameters and fixed-point coefficients, then renders them in order while preserving overlap and concealment history. SPX noise words are reserved immediately after each block's mantissas, at their original position in the shared LFG sequence; rendering consumes those reserved words without advancing the generator again. The snapshot buffers use 152,792 bytes of static storage and no allocation. Packet sample counts, output-capacity checks and seek priming retain the same contract. This prepares the decoder for enhanced coupling's adjacent spectra; cross-frame lookahead and enhanced-coupling reconstruction remain pending.

`python3 tests/verify-eac3-blocks.py` checks this separation against the sequential model using conventional/SPX and AHT/SPX streams. It introduces a CRC-valid invalid SPX range in each of blocks 0–5, verifies the valid prefix and repeated last-block concealment, and checks recovery in the following frame. The native suite requires byte-exact model PCM for all 14 fixtures. `--prepare-only` and `--prepared` permit hash-checked generation on another machine; `--wine-only` compares the shipping Windows binary with the native output.

After this refactor, the AC-3, conventional E-AC-3, SPX, AHT and block-boundary suites pass 411 native checks and 245 Windows checks under Wine. The 13 E-AC-3 robustness sources pass 1,300 Linux mutations and 130 Wine mutations with seed 20261010; [the focused native report](../reports/eac3-blocks-robustness-verification.json) and [Wine report](../reports/eac3-blocks-robustness-wine-verification.json) preserve the run conditions. In the first Wine fuzz run, Wine 8 failed at startup while mapping shared user data. The saved input returned exit 2 in five subsequent Windows replays, matching Linux. The completed strict fuzz run used `setarch x86_64 -R` to disable address randomization for that test process; it retained exit-code and timeout checks. The Windows builds also pass with LLVM 14 and 23; layout-derived snapshot sizes use explicit immediate operands to prevent LLVM from interpreting them as addresses.

The suite's report records actual comparisons and coverage; it does not certify the unsupported tools.

After the Linux suite passes, `xvfb-run -a python3 tests/verify-eac3.py --wine-only` compares the shipping Windows CLI under Wine with Linux PCM, millisecond `--start` decodes and rejections. `tests/verify-robustness.py --only tone.ec3,written.ec3,eac3.mka,eac3.mp4,eac3.ts` mutates raw and container inputs, including random starts. The checked-in snapshots use Debian 12.15 x86-64 under QEMU TCG on ARM macOS, FFmpeg 5.1.9, Wine 8.0 and LLVM 14.0.6. The macOS cross-build also passes PE import/resource checks with LLVM 23.1.2. `dbus-run-session -- python3 tests/verify-eac3-spx.py` separately checks full-channel model PCM and assembly stereo PCM against FFmpeg, every SPX numeric code, partial/all-channel selection, default/explicit/reused bands, coordinate reuse, on/off transitions, wide-band wrapping, both exponent syntaxes, converted frames, all block lengths and all three rates. The writer leaves the object-extension flag clear in opaque metadata, so a one-byte field cannot accidentally advertise a missing complexity byte.

Afterward, `xvfb-run -a python3 tests/verify-eac3-spx.py --wine-only` checks shipping PE PCM and starts. The four new robustness sources are `spx.ec3,spx.mka,spx.mp4,spx.ts`; their separate reports preserve the conventional E-AC-3 fuzz results.

`dbus-run-session -- python3 tests/verify-eac3-aht.py` checks every VQ index and HEBAP level, all GAQ modes and gain/sign/escape paths, coupled/uncoupled and partial AHT selection, LFE, SPX combinations, exponent syntaxes, all channel modes and rates, converted frames, transitions between six-block AHT and shorter conventional frames, containers, 75 exact seeks, two noisy primer seeks, output-capacity guards, CRC concealment, truncation and sink playback. `--prepare-only` and `--prepared` use hash-checked fixtures and normative/compatibility model PCM, permitting generation on another host. `--wine-only` checks shipping Windows PCM and start positions against the completed native run. The additional robustness sources are `aht.ec3,aht.mka,aht.mp4,aht.ts`. The snapshot passes 119 native checks and 63 Windows checks under Wine, plus 2,000 Linux and 200 Wine mutations. All 32 native fixture decodes also equal the normative model PCM byte for byte; compatibility PCM against FFmpeg 5.1.9/9.0.1 is at 138 dB or better. **Reference exception:** stock FFmpeg 5.1.9, 6.1 and 9.0.1 omit index 0 of the HEBAP-4 VQ table, shifting indices 0–30 and leaving index 31 zero-filled. [ATSC Table E4.4](https://www.atsc.org/wp-content/uploads/2021/04/A52-2018.pdf) and [ETSI Table E.3.4](https://www.etsi.org/deliver/etsi_ts/102300_102399/102366/01.04.01_60/ts_102366v010401p.pdf) both specify all 32 rows, starting with `0x5903,0x15c0,0xe9e6,0xff64,0xfe06,0xffdf`. LAMP keeps the normative table. The suite checks full-channel model PCM against stock FFmpeg with only that table omission emulated in the test model, then checks assembly output against normative model PCM. The report labels the exception; arbitrary AHT streams are not claimed to match unmodified FFmpeg. A separate local FFmpeg 6.1 reference with the missing numeric row restored also matched the normative model above 139 dB across all four GAQ modes.

## Provenance

The parser and SPX reconstruction are handwritten from [ATSC A/52:2018 Annex E](https://www.atsc.org/wp-content/uploads/2021/04/A52-2018.pdf), including Section 3.6. Only numeric data from Tables E2.10 (frame exponent strategies), E2.11 (default SPX bands), E2.12 (default coupling bands) and E3.14 (SPX attenuation) enter `src/eac3_tables.inc`. `python3 tests/generate-eac3-tables.py --check` downloads the specification, checks SHA-256 `4580b631f5ac1aafdd31034f28d5fc9c29bce72a3d3f6367e3d9746906e0ffa1`, extracts those numeric rows using `pdftotext`, and verifies the generated include. Attenuation decimal values are stored as their IEEE float32 bit patterns. Poppler is a test-generation dependency. The PDF is cached outside version control.

`python3 tests/generate-eac3-aht-tables.py --check` extracts Tables E3.1 (HEBAP), E3.2 (bit widths), E3.6 (remapping) and E4.1–E4.7 (VQ), verifies every index and row count, and regenerates `src/eac3_aht_tables.inc` from the same pinned PDF. The inverse-transform Q23 cosine constants are derived and checked by the generator. No reference-decoder table or runtime implementation is imported.

FFmpeg is the external PCM/error-concealment comparator. Its runtime code is not copied or linked into LAMP. The existing AC-3 numeric tables retain their [MIT source notices](../THIRD_PARTY_NOTICES). No new runtime dependency is added.

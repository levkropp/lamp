# E-AC-3 partial profile

LAMP 0.4.0-dev adds a handwritten E-AC-3 parser in `src/eac3.inc`, spectral reconstruction in `src/eac3_spx.inc` and adaptive hybrid transform mantissas in `src/eac3_aht.inc`, sharing bit allocation, IMDCT, overlap, speaker mixing and the track layer with [AC-3](ac3.md). This is a partial E-AC-3 profile. Enhanced coupling now has experimental encoded-stream support following the literal ATSC equations; interoperability normalization and dependent substreams remain open.

## Profile v4 (enhanced coupling experimental)

- Independent and AC-3-converted substream 0, bitstream ids 11–16, 32/44.1/48 kHz, all eight channel modes with optional LFE, downmixed to stereo using LAMP's speaker weights.
- Frame lengths of 1, 2, 3 or 6 blocks (256, 512, 768 or 1,536 samples), including lengths changing within a stream. Sync frames are bounded to 4,096 bytes. Packets can hold several whole frames; the decoder checks output capacity before every frame.
- Conventional AC-3 mantissa quantizers, per-block and lookup-table exponent strategies, ordinary coupling with default or explicit band structures, implicit first coupling coordinates and leaks, phase flags, rematrixing, block switching, dither, dynamic range, frame-level SNR and FFmpeg-compatible block-0 SNR packing, separate fast gains, delta bit allocation and skip fields.
- Spectral extension (SPX): mono's implicit selection and per-channel selection in other modes, all copy/start/end codes within valid ranges, default/explicit/reused bands, implicit first and reused coordinates, all blend/master/exponent/mantissa codes, and all 32 attenuation codes. Float synthesis translates the coded coefficients, computes band RMS before attenuation, filters band boundaries and wrap points, and blends the signal with the same LFG used for mantissa dither. Ordinary coupling ends at the SPX start, and exponent/rematrix ranges follow the selected channels.
- Adaptive hybrid transform (AHT) in eligible six-block channels, including coupling and LFE channels, partial channel selection and SPX combinations. The decoder uses the high-efficiency allocation table, all 956 six-dimensional VQ vectors, all four gain modes, ternary grouped gains, small/escaped scalar mantissas, asymmetric remapping and a fixed-point six-point inverse cosine transform. Block zero reconstructs all six blocks into a bounded cache; later blocks apply their reused exponents without consuming more mantissa bits. Reserved gain-group codes 27–31 clamp to 26, agreeing with FFmpeg's concealment behavior.
- Experimental enhanced coupling (ECPL): valid begin/end codes, SPX-derived ends, default/explicit/reused bands, partial channel selection, implicit first and reused amplitude/phase/chaos coordinates, angle interpolation and transient flags. Carrier reconstruction uses the preceding, current and following raw coupling spectra, preserving each block's own range. Reconstruction remains floating point through DRC and SPX. Its normalization limitation is described below; full encoded-stream conformance is not claimed.
- Mixing, informational, converter, additional bitstream and transient fields are parsed to preserve bit alignment. Mixing/program-scale metadata does not override LAMP's speaker weights, transient pre-noise processing is not applied, and additional object metadata is not rendered.
- Raw `.ec3`, `.eac3` or `.ac3` sync streams, Matroska `A_EAC3`, progressive/fragmented MP4/MOV `ec-3`, and MPEG-TS using ATSC stream type 0x87, DVB descriptor 0x7a or `EAC3` registration. Raw recognition uses content. CLI track selection works through the existing container layer.

Per-block SNR-offset updates beyond the FFmpeg-compatible block-0 packing are outside this profile. The published Annex E pseudocode describes another packing for those updates; general acceptance of that syntax is not claimed. Each frame must initialize its SNR offsets; older-frame SNR reuse is rejected. If a frame uses coupling, it must begin in block 0; late-start coupling in the block-0 packing could inherit offsets from older frames and prevent exact seeking, so it is explicitly rejected.

Dependent channel substreams, additional independent substreams, reduced sampling rates, older-frame SNR reuse, and coupling first activated after block 0 return `decode_error=101`. Unsupported tools fail when their syntax is encountered; they are not replaced by concealment. Atmos/object rendering, dependent-channel reconstruction and complete E-AC-3 conformance are not claimed.

Malformed framing, layout/rate changes, reserved frame types and insufficient output capacity fail. CRC errors conceal the entire frame; invalid block contents conceal the remaining blocks using the previous block, as in the AC-3 decoder. A truncated final raw frame is dropped. Leading ID3v2 and trailing ID3v1 tags are skipped.

## Timing and validation

Sample counts come from each sync frame's block count. The shared track layer honors MP4 edit lists and packet durations, and a seek decodes the preceding packet to rebuild the overlap. For E-AC-3, when that packet contains only one block, it decodes one additional preceding packet to rebuild the ECPL carrier used by the overlap. Dither-free conventional streams seek exactly; dither after a seek has the same level but a different generator position. SPX also advances the LFG when mantissa dither is disabled. Fresh CLI `--start` decodes reseed that LFG when opening the stream; an in-stream codec reset preserves its progression. Noisy seeking does not promise continuous-noise identity. Exact SPX seek tests use nonzero translated signal, zero noise blend in every band, fresh coordinates and a stable band structure; they do not claim continuous-noise identity after arbitrary seeks.

AHT zero-bit bins always draw six LFG values, regardless of the channel's ordinary dither flag. Noisy AHT seeks are therefore compared to fresh primer decodes. Exact AHT seek fixtures verify that no zero-bit AHT bins occur; disabling the ordinary dither flag alone does not establish exact continuous-noise seeking.

The E-AC-3 frame path separates block parsing from synthesis in `src/eac3_blocks.inc`. It snapshots at most six blocks of parameters and fixed-point coefficients, then renders them in order while preserving overlap and concealment history. SPX noise words are reserved immediately after each block's mantissas, at their original position in the shared LFG sequence; rendering consumes those reserved words without advancing the generator again. The snapshot buffers now use 168,704 bytes including alignment, reserving six parameter rows, six fixed-point rows, six coupling spectra and bounded SPX noise rows, with no allocation. `src/eac3_lookahead.inc` parses only block zero of the next compatible, complete, CRC-valid frame, whether it is inside the packet or borrowed from the next track packet. It restores the current bit reader, frame syntax, final parameters and shared LFG exactly. Missing, incompatible, CRC-invalid, non-ECPL or malformed neighbors contribute zero; concealed blocks also clear the previous carrier history. Lookahead emits no samples and adds no EOF block. Borrowed pointers are dropped on every packet-decode return, including failure, so caller-owned memory need not survive the call. Packet counts and capacity checks retain their existing contract.

`python3 tests/verify-eac3-blocks.py` checks this separation against the sequential model using conventional/SPX and AHT/SPX streams. It introduces a CRC-valid invalid SPX range in each of blocks 0–5, verifies the valid prefix and repeated last-block concealment, and checks recovery in the following frame. The native suite requires byte-exact model PCM for all 14 fixtures. `--prepare-only` and `--prepared` permit hash-checked generation on another machine; `--wine-only` compares the shipping Windows binary with the native output.

### Enhanced coupling and its validation limit

`src/eac3_ecpl.inc` now implements the carrier and channel-reconstruction kernels from A/52 Annex E Section 3.5.5. The carrier takes three explicitly supplied spectra, reuses the double-precision DCT-IV for their 512-sample windowed IMDCTs, overlaps them, applies the complex analysis rotation and performs a normalized 512-point FFT. Callers must zero each spectrum outside that block's own coupling range and supply zero for a neighbor without enhanced coupling. The channel kernel expands amplitudes, interpolates wrapped phase angles between band centers, applies chaos compensation and supplied random values, and projects the rotated carrier back to coefficients. It writes only the selected bins. Invalid band counts, flags, boundaries or numeric codes return failure before any output write. The kernels use 21,184 bytes of static scratch and no allocation or new runtime dependency.

`python3 tests/verify-eac3-ecpl-dsp.py` checks these kernels against test-only C that computes the IMDCT and DFT directly with cosine sums, without using LAMP's FFT, DCT-IV or generated tables. Its 238 cases cover all amplitude/phase/chaos codes, every flag combination, isolated previous/current/next spectra, changing neighbor ranges, merged and single bands, wraparound, endpoint extrapolation, odd/even band sizes, and malformed descriptors. Read-only inputs, output canaries and protected pages check memory boundaries; complex output deliberately has only eight-byte alignment. `--prepare-only` and `--prepared` use SHA-256 checked input/reference files. `--wine-only` links the same shipping COFF objects into a test executable with MinGW C helpers and checks them under Wine. The test executable's C runtime is not linked into LAMP.

All 238 cases pass on x86-64 Linux and with LLVM 14 COFF objects under Wine 8. The largest carrier deviation from the direct reference is below 8e-16. [Native results](../reports/eac3-ecpl-dsp-verification.json) and [Wine results](../reports/eac3-ecpl-dsp-wine-verification.json) record fixture and reference-source hashes. The macOS Windows cross-build also passes with LLVM 23 and retains LAMP's existing DLL imports.

Normalization follows the literal published equations: IMDCT steps 1–5, overlap without the ordinary decoder's factor of two, and DFT division by 512. The tests explicitly check the resulting half-gain identity for unit amplitude and zero phase. [The reviewed OxideAV implementation at its pinned revision](https://github.com/OxideAV/oxideav-ac3/blob/99228831d2b29a35fe2b2035118a18f8cb0cae59/src/eac3/ecpl.rs) instead inserts a factor of two and calls it an erratum. That interpretation has not been established from a primary-source correction in this work and is not silently adopted. Kernel agreement with direct specification math does not establish encoded-stream interoperability. Profile v4 accepts ECPL experimentally with this literal normalization. Independent encoded-stream encoder/decoder validation is still needed before claiming interoperability or complete E-AC-3 conformance.

`src/eac3_ecpl_stream.inc` connects the syntax to these kernels. A separate deterministic xorshift sequence supplies non-normative ECPL random values: one fixed per-channel/bin array is initialized once per process, while transient channels draw one fresh value per band per rendered block. Transient history resets with the codec; opening a stream reseeds the separate shared mantissa/SPX LFG. ECPL random draws do not consume that LFG. Exact seek fixtures contain no zero-bit coupling bins and use zero chaos; noisy one-block seeks are compared to fresh two-packet primers rather than continuous noise history.

`python3 tests/verify-eac3-ecpl.py --prepare-only` writes 31 hash-pinned fixtures using the separate full-stream model in `tests/eac3_ecpl_model.py`. All 31 raw fixture outputs are byte-exact with the model. A negative control removes next-frame spectra and changes 80,654 PCM bytes, proving that zero-at-packet-end substitution would fail. Guarded packet oracles compare joined/separate packets and reopened streams, check capacity canaries, and test CRC-invalid, malformed-sync, incompatible-rate and undersized borrowed neighbors. A lifetime regression protects the borrowed page after one decode and verifies the next decode without a setter; it reproduced a segmentation fault before the pointer-lifetime fix. ## Provenance

The parser and SPX reconstruction are handwritten from [ATSC A/52:2018 Annex E](https://www.atsc.org/wp-content/uploads/2021/04/A52-2018.pdf), including Section 3.6. Only numeric data from Tables E2.10 (frame exponent strategies), E2.11 (default SPX bands), E2.12 (default coupling bands) and E3.14 (SPX attenuation) enter `src/eac3_tables.inc`. `python3 tests/generate-eac3-tables.py --check` downloads the specification, checks SHA-256 `4580b631f5ac1aafdd31034f28d5fc9c29bce72a3d3f6367e3d9746906e0ffa1`, extracts those numeric rows using `pdftotext`, and verifies the generated include. Attenuation decimal values are stored as their IEEE float32 bit patterns. Poppler is a test-generation dependency. The PDF is cached outside version control.

`python3 tests/generate-eac3-aht-tables.py --check` extracts Tables E3.1 (HEBAP), E3.2 (bit widths), E3.6 (remapping) and E4.1–E4.7 (VQ), verifies every index and row count, and regenerates `src/eac3_aht_tables.inc` from the same pinned PDF. The inverse-transform Q23 cosine constants are derived and checked by the generator. No reference-decoder table or runtime implementation is imported.

`python3 tests/generate-eac3-ecpl-tables.py --check` extracts Tables E2.13 and E3.9–E3.12 (subband boundaries, amplitudes, angles and chaos) from the same hash-checked PDF and derives bit reversal, analysis/FFT rotations and the coefficient projection cosine. The chaos table retains the specification's printed six-decimal values. Numeric doubles are stored as their IEEE bit patterns; no external decoder's runtime or tables are imported.

FFmpeg is the external PCM/error-concealment comparator. Its runtime code is not copied or linked into LAMP. The existing AC-3 numeric tables retain their [MIT source notices](../THIRD_PARTY_NOTICES). No new runtime dependency is added.
